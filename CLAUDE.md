# aggregate-R

Adds to `V:\dev\CLAUDE.md` (the dev tree) and the house rules. Project detail only.

`aggregateR` is an R package that puts the `aggregate` actuarial library in R by talking over
HTTP to `aggregate-api`, the FastAPI service in the sibling repo `../aggregate-api`. The repo is
`aggregate-R`, but the package is `aggregateR`, because R package names cannot contain a hyphen.
R never hosts Python. reticulate was tried and rejected for its environment and conversion pain. The package
is a thin client, and the API is its contract. The design and its rationale live in
`dev/plan-r-client.md`; read that before proposing changes to the approach.

## Relationship to aggregate-api

- **The API is the contract, and this repo never changes it.** If the client needs a route, a
  parameter or a format, that is a plan in `aggregate-api`, landed there first. Build against
  routes that exist, not ones still being drafted.
- **The Excel add-in is the reference client.** `../aggregate-api/excel/src/functions/core.ts`
  already handles these cases:
  - handles, and rebuilding an evicted object from its recipe
  - a DecL program passed in place of a handle
  - the session header, `X-Aggregate-Session`
  - flattening a multi-block exhibit into a grid
  - turning a refusal into readable text

  Port its decisions rather than re-deriving them, and say where R departs.
- **The route list is `/openapi.json` on any running server** (Swagger UI at `/docs`). Don't
  copy it here, where it would drift.
- **Servers:** the client talks to either the public `https://agg.mynl.com` or a local
  `aggregate-api` that the package's launcher starts on `127.0.0.1`. A user's programs are their
  data, and anything sent to the public server has left their machine. The docs say so wherever
  the user chooses a server.

## Stack

- **Pure R, no compiled code**, so Rtools is not needed. R >= 4.1, the floor `httr2` sets.
- **Imports:**
  - `httr2` for requests, retries and errors
  - `jsonlite` for JSON
  - `nanoparquet` for frames as Parquet. It has no dependencies of its own and has read zstd and
    byte stream split since 0.3.0.
  - `processx` for the local launcher

  Each import is installed by every user, so adding one is the author's decision.
- **Development:** `devtools`, `usethis`, `roxygen2`, `testthat` (third edition).
- **Style:**
  - Tidyverse style and snake_case.
  - Every exported function is `agg_*`.
  - Package code uses base R rather than tidyverse dependencies, and returns plain
    `data.frame`s.

## Layout

The standard package layout:

- `DESCRIPTION`: metadata, imports and the version.
- `NAMESPACE` and `man/`: both generated by roxygen2. Never edit them by hand.
- `R/`: the code.
- `tests/testthat/`: the tests and their fixtures.
- `vignettes/`
- `dev/`: plans, listed in `.Rbuildignore`.

## Commands

R's installer does not put R on `PATH`. Find `Rscript.exe` from the registry rather than
hard-coding a path: the `InstallPath` value under `HKLM:\SOFTWARE\R-core\R`, then
`bin\Rscript.exe`. From the repo root:

```
Rscript -e "devtools::document()"   # regenerate NAMESPACE and man/ from roxygen comments
Rscript -e "devtools::test()"       # unit tests, no server needed
Rscript -e "devtools::check()"      # R CMD check, the CRAN gate; run before every bump
```

In RStudio, open the `.Rproj`. `devtools::load_all()` (Ctrl+Shift+L) loads the package live,
the counterpart of an editable install.

## Tests

- **Unit tests need no server.** HTTP responses are recorded fixtures under
  `tests/testthat/fixtures/`, built from synthetic DecL and library programs only.
- **Live tests are opt-in.** They run against a local server, behind an environment variable
  named in the plan, and are skipped on CRAN and when offline. They never touch the public
  server.

## Versioning

Single-sourced in `DESCRIPTION` (`Version:`), which `packageVersion()` reads. House SemVer
applies, with no `.9000` development suffix.

## Deltas from house rules

- **"Develop and test ONLY against synthetic fixtures committed under `fixtures/`."** Fixtures
  live in `tests/testthat/fixtures/` instead. `R CMD check` runs the tests from the built
  package, which cannot see a top-level `fixtures/`. They are still synthetic only.
- **The CHANGELOG is `NEWS.md`, not `CHANGELOG.md`.** R's `utils::news()`, CRAN and pkgdown all
  read that file.
  - Each entry is headed `# aggregateR x.y.z (YYYY-MM-DD)`, with `## Added`, `## Changed` and
    `## Fixed` under it.
  - Otherwise the Keep a Changelog discipline and entry size are unchanged.
- **The dev tree's stack defaults (Python, uv, Flask, NumPy docstrings) don't apply.**
  Documentation is roxygen2: `#'` comments above each function, rendered to `man/`. They cover
  the same ground as a docstring: a description, `@param`, `@return`, `@examples`, and a
  `@details` section for the why.
